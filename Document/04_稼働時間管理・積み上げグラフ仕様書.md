# 04. 稼働時間管理・積み上げグラフ仕様書

## 1. 目的と要件
本機能は、以下のユーザー要件に基づき実装されました。

1. **週報登録時の稼働時間入力**: 各メンバーが週報を提出する際、その週の実働稼働時間（h）を入力・保持する。
2. **管理画面とは別リンクの配置**: 管理者専用の `/admin` とは切り離し、マネージャーが素早くアクセスできる専用リンクを設置する。
3. **配下メンバーの稼働時間 積み上げグラフ表示**: マネージャーが管轄する組織配下の全メンバーの稼働時間を、週ごとの積み上げ棒グラフ（Stacked Bar Chart）で可視化する。

---

## 2. 稼働時間のデータ保持仕様

### 2.1 スキーマ定義
- テーブル: `weekly_reports`
- カラム: `workHours Float @default(40.0)`
- 単位: 時間（Hours）、小数点以下第1位まで（例: `42.5`）
- デフォルト値: `40.0` 時間（所定労働時間目安）

### 2.2 登録・更新フロー
1. ユーザーが「週報を作成する」ボタンをクリック。
2. モーダル内の「その週の実働稼働時間」入力欄に値を入力（ステップ値: `0.5`）。
3. 45.0時間を超過した場合は、入力欄直下に過重労働注意のアラートバッジが表示される。
4. 送信時、Server Action `createReport` が `workHours` をバリデーション（0〜168時間以内）の上、データベースへUPSERT保存。

---

## 3. 配下組織・メンバーの再帰集約ロジック

マネージャー（`MANAGER`）が自部門およびその傘下にあるすべての子部門メンバーの稼働時間を串刺し集約するためのロジック仕様です。

```
[開発本部 (マネージャー: 高橋健二)]
   ├── [フロントエンド開発部] ── 山田 太郎
   └── [バックエンド開発部]   ── 渡辺 大樹
```

### 3.1 再帰取得アルゴリズム (`src/app/actions.ts` 内 `getManagerWorkHoursAnalytics`)
1. **マネージャー所属部門の特定**: ログインユーザーの `departmentId` を取得。
2. **配下子部門の再帰探索**:
   - `getDescendantDepartmentIds(user.departmentId)` を呼び出し、BFS（幅優先探索）で自部門自身 + 子部門 + 孫部門の全IDを収集。
3. **メンバー一覧の取得**:
   - 収集した部門ID群に所属する全 `User` を取得。
4. **週報データの取得と週別集計**:
   - 対象メンバーの過去〜最新週の週報を一括取得。
   - 週（`year-weekNumber`）ごとにメンバー別の稼働時間をマッピングし、積み上げ合計（`totalHours`）と平均（`averageHours`）を計算。
5. **管理者の場合**:
   - ロールが `ADMIN` の場合は、全社全組織の全メンバーを対象として集計（全社俯瞰が可能）。

### 4.2 主要インタラクション機能
1. **横軸（人 / メンバー）× 縦方向（各週）の積み上げ**:
   - 横軸に配下のメンバーを並べ、縦方向に各週（第38週、第39週、第40週、第41週…）の稼働時間を下から積み上げて表示。バーの上部には期間合計稼働時間（例: `166.5h`）を表示。
2. **週別カラーパレット**:
   - 各週に固有の識別カラー（Indigo, Emerald, Cyan, Amber, Purple 等）を自動割り当て。
3. **ホバーツールチップ**:
   - 積み上げバーの各ブロックにマウスを重ねると、メンバー名、所属部門、対象週、稼働時間、および提出週報タイトルがフローティング表示される。
4. **週凡例ハイライト**:
   - 上部の週凡例ボタンをクリックすると、選択した特定週のブロック以外が半透明になり、複数メンバー間での特定週の稼働負荷の比較が容易に行える。
5. **過重労働（45h超過）アラート枠線**:
   - 週45時間を超過した週のブロックには強調枠線（Roseカラー）が付与され、下部一覧テーブル側にも警告アイコン（`⚠️`）が表示される。
6. **組織絞り込みフィルター**:
   - ドロップダウンから管轄下の子部門を選択することで、特定部門のみのメンバー積み上げグラフに瞬時に切り替え可能。
