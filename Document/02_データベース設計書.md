# 02. データベース設計書

## 1. 概要
データベースには PostgreSQL 16 を採用し、Prisma ORM を通じてスキーマ定義およびマイグレーション・クエリ実行を行っています。

## 3. テーブル定義

### 3.1 `departments`（部門テーブル）
組織の階層構造を表現するため、自己参照リレーション（Adjacency List）を採用しています。

| カラム名 | 型 | NULL | 初期値 | 説明 |
| :--- | :--- | :---: | :--- | :--- |
| `id` | TEXT (cuid) | NO | `cuid()` | 部門ID（主キー） |
| `name` | TEXT | NO | - | 部門名称（例: 開発本部, フロントエンド開発部） |
| `parentId` | TEXT | YES | NULL | 親部門ID（NULLの場合はトップレベル部門/本部） |
| `order` | INTEGER | NO | 0 | 同一階層内での並び順 |
| `createdAt` | TIMESTAMP | NO | `now()` | 作成日時 |
| `updatedAt` | TIMESTAMP | NO | `now()` | 更新日時 |

- **リレーション**:
  - `parent`: `departments.id` への参照（親部門）
  - `children`: 自部門を `parentId` とする子部門リスト
  - `users`: 所属するユーザー一覧（`1:N`）

---

### 3.2 `users`（ユーザーテーブル）

| カラム名 | 型 | NULL | 初期値 | 説明 |
| :--- | :--- | :---: | :--- | :--- |
| `id` | TEXT (cuid) | NO | `cuid()` | ユーザーID（主キー） |
| `email` | TEXT | NO | - | ログインメールアドレス（UNIQUE） |
| `passwordHash`| TEXT | NO | - | bcrypt による暗号化パスワード |
| `name` | TEXT | NO | - | 氏名（例: 山田 太郎） |
| `role` | `Role` (ENUM) | NO | `MEMBER` | 権限（`MEMBER` / `MANAGER` / `ADMIN`） |
| `departmentId`| TEXT | YES | NULL | 所属部門ID（外部キー: `departments.id`） |
| `createdAt` | TIMESTAMP | NO | `now()` | 作成日時 |
| `updatedAt` | TIMESTAMP | NO | `now()` | 更新日時 |

---

### 3.3 `weekly_reports`（週報テーブル）

| カラム名 | 型 | NULL | 初期値 | 説明 |
| :--- | :--- | :---: | :--- | :--- |
| `id` | TEXT (cuid) | NO | `cuid()` | 週報ID（主キー） |
| `userId` | TEXT | NO | - | 提出者ユーザーID（外部キー: `users.id`） |
| `startDate` | TIMESTAMP | NO | - | 対象週の開始日（月曜日） |
| `endDate` | TIMESTAMP | NO | - | 対象週の終了日（金曜日） |
| `year` | INTEGER | NO | - | 対象年（例: 2026） |
| `weekNumber`| INTEGER | NO | - | ISO週番号（例: 41） |
| `title` | TEXT | NO | - | 週報タイトル |
| `content` | TEXT | NO | - | マークダウン形式の週報本文 |
| `workHours` | DOUBLE PRECISION| NO | 40.0 | **その週の実働稼働時間（積み上げ集計用）** |
| `status` | `ReportStatus` | NO | `SUBMITTED` | 提出状態（`DRAFT`: 下書き, `SUBMITTED`: 提出済） |
| `submittedAt`| TIMESTAMP | YES | NULL | 提出確定日時 |
| `createdAt` | TIMESTAMP | NO | `now()` | 作成日時 |
| `updatedAt` | TIMESTAMP | NO | `now()` | 更新日時 |

- **制約・インデックス**:
  - `@@unique([userId, year, weekNumber])`: 同一メンバーが同一週に登録できる週報は1件のみ（UPSERT処理に利用）。
  - `@@index([year, weekNumber])`: 週単位での集計クエリを高速化。
  - `@@index([userId])`: ユーザー別一覧取得を高速化。

---

### 3.5 `user_checks`（★チェック対象メンバーテーブル）

| カラム名 | 型 | NULL | 初期値 | 説明 |
| :--- | :--- | :---: | :--- | :--- |
| `id` | TEXT (cuid) | NO | `cuid()` | チェックID（主キー） |
| `userId` | TEXT | NO | - | チェックを行ったユーザーID（外部キー: `users.id`） |
| `targetId` | TEXT | NO | - | チェック対象のユーザーID（外部キー: `users.id`） |
| `createdAt` | TIMESTAMP | NO | `now()` | 登録日時 |

- **制約**:
  - `@@unique([userId, targetId])`: 同一ユーザーに対する二重チェックを防止
  - `@@index([userId])`, `@@index([targetId])`

---

### 3.6 `report_likes`（週報いいねテーブル）

| カラム名 | 型 | NULL | 初期値 | 説明 |
| :--- | :--- | :---: | :--- | :--- |
| `id` | TEXT (cuid) | NO | `cuid()` | いいねID（主キー） |
| `reportId` | TEXT | NO | - | 対象週報ID（外部キー: `weekly_reports.id`） |
| `userId` | TEXT | NO | - | いいねを押したユーザーID（外部キー: `users.id`） |
| `createdAt` | TIMESTAMP | NO | `now()` | 登録日時 |

- **制約**:
  - `@@unique([reportId, userId])`: 同一週報への多重いいね防止
  - `@@index([reportId])`, `@@index([userId])`

## 4. Prisma スキーマ定義コード抜粋 (`prisma/schema.prisma`)

```prisma
enum Role {
  ADMIN
  MANAGER
  MEMBER
}

enum ReportStatus {
  DRAFT
  SUBMITTED
}

model ReportLike {
  id        String       @id @default(cuid())
  reportId  String
  report    WeeklyReport @relation(fields: [reportId], references: [id], onDelete: Cascade)
  userId    String
  user      User         @relation(fields: [userId], references: [id], onDelete: Cascade)
  createdAt DateTime     @default(now())

  @@unique([reportId, userId])
  @@index([reportId])
  @@index([userId])
  @@map("report_likes")
}

model UserCheck {
  id        String   @id @default(cuid())
  userId    String
  user      User     @relation("UserChecks", fields: [userId], references: [id], onDelete: Cascade)
  targetId  String
  target    User     @relation("TargetChecked", fields: [targetId], references: [id], onDelete: Cascade)
  createdAt DateTime @default(now())

  @@unique([userId, targetId])
  @@index([userId])
  @@index([targetId])
  @@map("user_checks")
}

model Department {
  id        String       @id @default(cuid())
  name      String
  order     Int          @default(0)
  parentId  String?
  parent    Department?  @relation("DepartmentHierarchy", fields: [parentId], references: [id], onDelete: SetNull)
  children  Department[] @relation("DepartmentHierarchy")
  users     User[]
  createdAt DateTime     @default(now())
  updatedAt DateTime     @updatedAt

  @@map("departments")
}

model WeeklyReport {
  id          String       @id @default(cuid())
  userId      String
  user        User         @relation(fields: [userId], references: [id], onDelete: Cascade)
  startDate   DateTime
  endDate     DateTime
  year        Int
  weekNumber  Int
  title       String
  content     String       @db.Text
  workHours   Float        @default(40.0) // 稼働時間 (h)
  status      ReportStatus @default(SUBMITTED)
  submittedAt DateTime?
  comments    Comment[]
  createdAt   DateTime     @default(now())
  updatedAt   DateTime     @updatedAt

  @@unique([userId, year, weekNumber])
  @@index([year, weekNumber])
  @@index([userId])
  @@map("weekly_reports")
}
```
